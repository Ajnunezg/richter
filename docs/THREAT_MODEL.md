# Richter Threat Model

**Version:** 1.0
**Date:** 2026-05-19
**Scope:** Richter daemon, CLI, MCP server, mobile companion gateway

## System Overview

Richter is a local agent-control plane that runs entirely on the user's macOS machine. It exposes:
1. A Unix domain socket API (local only, authenticated)
2. An MCP server (stdio or local HTTP)
3. An optional mobile gateway (localhost or LAN, TLS, device-authenticated)

## STRIDE Analysis

### S — Spoofing

| Threat | Risk | Mitigation | Status |
|--------|------|------------|--------|
| Agent spoofs another agent's identity | Medium | Agent IDs generated by daemon, not client | Mitigated |
| Mobile device spoofs paired device | High | Ed25519 challenge-response per request | Mitigated |
| CLI process uses stolen auth token | Medium | Token is 256-bit random, rotated on restart, 0600 permissions | Mitigated |
| LLM provider impersonates API endpoint | Low | TLS + certificate validation via reqwest/rustls | Mitigated |

### T — Tampering

| Threat | Risk | Mitigation | Status |
|--------|------|------------|--------|
| Agent injects shell metacharacters in commands | High | `shlex` round-trip validation + blocklist of `$()`, `` ` ``, `&&`, `\|\|`, `;`, `\|` | Mitigated |
| Agent injects dangerous environment variables | High | Env denylist: PATH, LD_PRELOAD, LD_LIBRARY_PATH, DYLD_* | Mitigated |
| Agent modifies command after fingerprint | Medium | Fingerprint computed from classified command, immutable after | Mitigated |
| Tampered database file | Medium | 0600 permissions, integrity check on startup | Partial — no at-rest encryption |
| Mobile device sends tampered request body | Medium | X-Body-Hash header, Ed25519 signature over (timestamp + nonce + body hash) | Mitigated |
| Plugin binary tampered after installation | High | SHA-256 hash verification against trusted.json | Mitigated |
| Webhook payload tampered in transit | Medium | HMAC-SHA256 signature on all webhook payloads | Mitigated |

### R — Repudiation

| Threat | Risk | Mitigation | Status |
|--------|------|------------|--------|
| Agent denies submitting a command | Low | Command invocations recorded with agent_id, timestamp, fingerprint | Mitigated |
| Mobile device denies an action | Medium | Full audit log in mobile_gateway_audit_log table | Mitigated |
| User denies changing settings | Low | Settings table with timestamps | Mitigated |

### I — Information Disclosure

| Threat | Risk | Mitigation | Status |
|--------|------|------------|--------|
| Secrets in command output stored in DB | High | Redaction engine runs at capture time + before model calls | Mitigated |
| Auth token readable by other users | Medium | 0600 permissions, auto-corrected on startup | Mitigated |
| Database file readable by other users | Medium | 0600 permissions on DB file | Partial — no at-rest encryption |
| LLM provider sees secrets in payloads | High | Redaction applied before model calls, 4KB truncation | Mitigated |
| Logs contain sensitive data | Medium | Secrets redaction applied to log output | Mitigated |
| Mobile API exposes sensitive endpoints | Medium | Scope-based auth, no secrets in API responses | Mitigated |

### D — Denial of Service

| Threat | Risk | Mitigation | Status |
|--------|------|------------|--------|
| Agent floods daemon with run requests | Medium | Token bucket rate limiter (300 RPM default), per-client | Mitigated |
| Agent submits extremely large commands | Low | MAX_COMMAND_LENGTH (4096 bytes) enforced | Mitigated |
| Process output consumes all memory | Medium | MAX_OUTPUT_BUFFER_BYTES (1MB per run) enforced | Mitigated |
| Mobile device floods gateway | Medium | Per-device rate limiting, pairing required | Mitigated |
| Stuck process blocks scheduler | Low | NO_OUTPUT_TIMEOUT (5min), process group kill on timeout | Mitigated |

### E — Elevation of Privilege

| Threat | Risk | Mitigation | Status |
|--------|------|------------|--------|
| Agent escapes process sandbox | High | Runs as current user (no root), process group isolation, no SUID | Mitigated |
| Plugin executes arbitrary code | High | Hash verification, structural validation, capability restriction | Mitigated |
| Agent reads another agent's output | Medium | Output scoped to run_id, subscribers tracked | Partial — Unix permissions model |
| Mobile device escalates scopes | Medium | Scope granted at pairing, enforced per-request, auditable | Mitigated |

## Attack Surface Summary

### Highest Risk Surfaces

1. **Command execution path** — Agents submit arbitrary commands that are executed via `sh -c`. Mitigated by classification, injection prevention, and env denylist, but remains the highest-value attack target.

2. **Plugin runtime** — Executes binaries from `~/.richter/plugins/`. Code-signature verification exists but is macOS-dependent. A compromised plugin can execute arbitrary code as the user.

3. **Database at rest** — Not encrypted. Protected only by filesystem permissions. A machine compromise or backup leak exposes all Richter state.

### Lowest Risk Surfaces

1. **Unix domain socket** — Local only, authenticated with high-entropy token, constant-time comparison.
2. **Secrets redaction** — Comprehensive pattern coverage, applied at multiple layers.
3. **MCP server** — Stdio transport is local-only by definition.

## Recommendations

1. **Integrate SQLCipher** for at-rest database encryption (highest priority).
2. **Add sandboxing** for spawned child processes (e.g., `sandbox-exec` on macOS).
3. **Sign daemon binary** with a developer certificate to prevent tampering.
4. **Add audit logging** for all API write operations (not just mobile).
5. **Implement certificate pinning** for LLM provider HTTPS calls.
